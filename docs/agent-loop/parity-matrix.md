# Agent loop parity matrix

**14 Nov 2026 · PR #992 (`AGENT_LOOP_ENABLED`) · for QA** · describes `claude/agent-loop` at commit `87ea470c`

Today the HR chat answers through a long chain of hand-coded handlers, each fix behind a production flag. With `AGENT_LOOP_ENABLED` on (and the manager listed in `AGENT_LOOP_USERS`), the turn is answered by a model that calls tools instead. This matrix shows, behaviour by behaviour, how the loop reproduces what today's production flags do, and where it does not.

**How to read it**

- One row per behaviour. Every one of the 392 flags in the `on` list of `src/config/production-flags.json` is in exactly one row; the [Flag index](#flag-index) at the end lists them alphabetically with their row. In the tables, flags are written without the `_ENABLED` suffix.
- **how the loop does it**:
  - `RULE <section>: “…”` quotes the rules book (`src/lib/ai/agent-loop/rules-book.ts`). The model is told this; no code enforces it.
  - `TOOL <name>` is code in `tools.ts` / `run.ts` (or today's helper it calls) that produces the behaviour.
  - `HARD GUARD <name>` is code that refuses or overrides whatever the model does.
  - `N/A — …` means the flag is not about the chat answer (Create / draft route, Woven sync, storage, forms UI) or belongs to a handler the loop replaces.
  - `GAP — …` means the loop has no rule, tool or guard for that chat behaviour (or only for part of it).
- **replay case**: a case in `src/app/api/chat/replay-pack/`. `nov14-agent-loop-…` cases run with the loop on in CI (their "holds with AGENT_LOOP_ENABLED on" arm). Other ids are existing cases with the flag in `fixFlags`; they reach the loop only in the live runs (`AGENT_LOOP_LIVE_ALL`). `—` means no case found.
- **live-sampled**: `y` if any listed case id is in `scripts/agent-loop-live/cases-*.txt` (run against the real model), else `n`.
- Totals: 111 rows, 19 with a GAP, 17 N/A.

The Create button, the draft route and the forms register run the same code with the loop on. Rows marked "Create / draft route" rely on that; they were not re-tested with loop-made cards beyond the replay cases named.
